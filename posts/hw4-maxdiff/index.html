Introduction

In this assignment, I analyze how MSBA students at UC San Diego Rady School of Management rank their 10 core classes using a MaxDiff (Best-Worst Scaling) survey.

What is MaxDiff?
In a MaxDiff survey, each screen shows a small set of items (here, 4 classes). The respondent picks the most preferred and least preferred item from that screen. This repeats across many screens. Unlike asking “rate each class from 1–10,” MaxDiff forces real trade-offs, which makes the data more reliable and avoids the problem of everyone giving everything a 7.

Why MaxDiff instead of rating scales?
Humans are much better at comparing and ranking than at using abstract numeric scales consistently. MaxDiff removes scale-use bias by turning every question into a concrete trade-off.

Three methods to analyze the data:

  1. Counts Analysis — a simple descriptive score: % times picked best minus % times picked worst
  2. MNL via Maximum Likelihood (MLE) — a formal statistical model with point estimates and standard errors
  3. MNL via Bayesian (MCMC) — same model but with full posterior distributions and credible intervals

All three should agree on the broad ranking of classes. The main differences are in how they quantify uncertainty and handle the underlying choice process.

Counts Analysis

The simplest way to summarize MaxDiff data is the counts score: for each class, compute the percentage of times it was picked best minus the percentage of times it was picked worst.

\[\text{score}_j = \%\text{best}_j - \%\text{worst}_j\]

A score near +1 means students almost always prefer this class when shown; near −1 means it is almost always avoided; near 0 means it is middle-of-the-pack or polarizing.

From MaxDiff Data to MNL Choices

The Multinomial Logit (MNL) model assigns each class \(j\) a utility coefficient \(\beta_j\). On a task showing 4 classes \(\{a, b, c, d\}\), the probability of picking \(b\) as best is the softmax:

\[P(\text{best} = b) = \frac{\exp(\beta_b)}{\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)}\]

After choosing best, the worst is picked from the remaining 3 classes with flipped utilities:

\[P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)}{\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)}\]

Each task therefore contributes two MNL observations to the likelihood.

Identifiability: The softmax is invariant to adding a constant to all \(\beta\)’s, so we can only identify differences in utility. We fix \(\beta_1 = 0\) (AI Math as the reference class) and estimate \(\beta_2, \ldots, \beta_{10}\).

MNL via Maximum Likelihood

The log-likelihood sums over all tasks:

\[\ell(\boldsymbol\beta) = \sum_{\text{tasks}} \left[ \beta_{j^*_b} - \log\!\sum_{j \in \text{shown}} e^{\beta_j} \;-\; \beta_{j^*_w} - \log\!\!\sum_{j \in \text{shown} \setminus \{j^*_b\}} e^{-\beta_j} \right]\]

where \(j^*_b\) = item picked best, \(j^*_w\) = item picked worst.

Code 
# Log-likelihood function
# beta = length-9 vector for items 2-10; item 1 is pinned to 0
log_likelihood <- function(beta, tasks) {
  beta_full <- c(0, beta)   # full 10-vector with beta_1 = 0
  ll <- 0

  for (i in seq_len(nrow(tasks))) {
    shown      <- tasks$items[[i]]
    best_item  <- tasks$best[i]
    worst_item <- tasks$worst[i]

    # Best pick: softmax over all 4 shown items
    ll <- ll + beta_full[best_item] - log(sum(exp(beta_full[shown])))

    # Worst pick: softmax over remaining 3 with negated utilities
    remaining <- shown[shown != best_item]
    ll <- ll - beta_full[worst_item] - log(sum(exp(-beta_full[remaining])))
  }

  return(ll)
}

# Maximize the log-likelihood with BFGS
set.seed(42)

MNL via Bayesian Estimation

We fit the same MNL using a Metropolis-Hastings (MH) MCMC sampler. Instead of a single point estimate, we get a full posterior distribution over each \(\beta_j\).

Prior: \(\boldsymbol\beta \sim \mathcal{N}(\mathbf{0},\ 10 \cdot I)\) — weakly informative (SD ≈ 3.2), letting the data dominate.

Posterior: \(\pi(\boldsymbol\beta \mid \text{data}) \propto L(\boldsymbol\beta) \cdot \pi(\boldsymbol\beta)\)

Code 
# Log-posterior = log-likelihood + log-prior (N(0, 10) on each beta)
log_prior     <- function(beta) sum(dnorm(beta, 0, sqrt(10), log = TRUE))
log_posterior <- function(beta, tasks) log_likelihood(beta, tasks) + log_prior(beta)

# Metropolis-Hastings sampler
mh_sampler <- function(beta0, n_iter, step, tasks) {
  K      <- length(beta0)
  draws  <- matrix(NA, n_iter, K)
  beta   <- beta0
  lp     <- log_posterior(beta, tasks)
  accept <- 0

  for (t in 1:n_iter) {
    # Propose: random walk step
    beta_star <- beta + rnorm(K, 0, step)
    lp_star   <- log_posterior(beta_star, tasks)

    # Accept with MH probability
    if (log(runif(1)) < lp_star - lp) {
      beta   <- beta_star
      lp     <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  list(draws = draws, accept_rate = accept / n_iter)
}

Discussion

Substantive findings: MSBA students most prefer Customer Analytics and Marketing Analytics — courses with direct career application. BI Systems and Capstone score lowest, possibly because students view them as requirements rather than elective interests, or because they are less directly associated with data science job skills.

Methodological takeaways:

Method Best for
Counts Quick descriptive summary; executive dashboard; no modeling assumptions
MLE MNL Rigorous point estimates with standard errors; single number to report
Bayesian MNL Uncertainty on derived quantities (shares, simulations); hierarchical individual-level extensions

Caveats: This survey was completed by a self-selected group of current MSBA students. Preferences may vary by prior work experience, course order, and academic background. Students who have already completed a class may rate it differently than those who have not yet taken it.

Next steps: With more time, I would extend the Bayesian model to a hierarchical (mixed) MNL — estimating individual-level \(\beta\)’s for each student — to reveal whether different subgroups have systematically different class preferences.

## Introduction

In this assignment, I analyze how MSBA students at UC San Diego Rady School of Management rank their 10 core classes using a **MaxDiff** (Best-Worst Scaling) survey.

**What is MaxDiff?**  
In a MaxDiff survey, each screen shows a small set of items (here, 4 classes). The respondent picks the *most preferred* and *least preferred* item from that screen. This repeats across many screens. Unlike asking "rate each class from 1–10," MaxDiff forces real trade-offs, which makes the data more reliable and avoids the problem of everyone giving everything a 7.

**Why MaxDiff instead of rating scales?**  
Humans are much better at comparing and ranking than at using abstract numeric scales consistently. MaxDiff removes scale-use bias by turning every question into a concrete trade-off.

**Three methods to analyze the data:**

1. **Counts Analysis** — a simple descriptive score: % times picked best minus % times picked worst
2. **MNL via Maximum Likelihood (MLE)** — a formal statistical model with point estimates and standard errors
3. **MNL via Bayesian (MCMC)** — same model but with full posterior distributions and credible intervals

All three should agree on the broad ranking of classes. The main differences are in how they quantify uncertainty and handle the underlying choice process.

## Counts Analysis

The simplest way to summarize MaxDiff data is the **counts score**: for each class, compute the percentage of times it was picked best minus the percentage of times it was picked worst.

$$\text{score}_j = \%\text{best}_j - \%\text{worst}_j$$

A score near +1 means students almost always prefer this class when shown; near −1 means it is almost always avoided; near 0 means it is middle-of-the-pack or polarizing.

```{r}
# Compute counts score for each item

  group_by(item) |>

    shown   = n(),
    n_best  = sum(response ==  1),

  mutate(
    pct_best  = n_best  / shown,
    pct_worst = n_worst / shown,
```

## From MaxDiff Data to MNL Choices

The **Multinomial Logit (MNL)** model assigns each class $j$ a utility coefficient $\beta_j$. On a task showing 4 classes $\{a, b, c, d\}$, the probability of picking $b$ as *best* is the softmax:

$$P(\text{best} = b) = \frac{\exp(\beta_b)}{\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)}$$

After choosing best, the worst is picked from the remaining 3 classes with **flipped** utilities:

$$P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)}{\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)}$$

Each task therefore contributes **two** MNL observations to the likelihood.

**Identifiability:** The softmax is invariant to adding a constant to all $\beta$'s, so we can only identify *differences* in utility. We fix $\beta_1 = 0$ (AI Math as the reference class) and estimate $\beta_2, \ldots, \beta_{10}$.

```{r}
# Reshape: one row per task, storing the 4 items shown + which was best + which was worst
tasks <- data |>
  group_by(resp_id, task) |>
  summarise(
    items = list(item),
    best  = item[response ==  1],
    worst = item[response == -1],
    .groups = "drop"
  )
```

## MNL via Maximum Likelihood

The log-likelihood sums over all tasks:

$$\ell(\boldsymbol\beta) = \sum_{\text{tasks}} \left[ \beta_{j^*_b} - \log\!\sum_{j \in \text{shown}} e^{\beta_j} \;-\; \beta_{j^*_w} - \log\!\!\sum_{j \in \text{shown} \setminus \{j^*_b\}} e^{-\beta_j} \right]$$

where $j^*_b$ = item picked best, $j^*_w$ = item picked worst.

```{r}
# Log-likelihood function
# beta = length-9 vector for items 2-10; item 1 is pinned to 0
log_likelihood <- function(beta, tasks) {
  beta_full <- c(0, beta)   # full 10-vector with beta_1 = 0
  ll <- 0

  for (i in seq_len(nrow(tasks))) {
    shown      <- tasks$items[[i]]
    best_item  <- tasks$best[i]
    worst_item <- tasks$worst[i]

    # Best pick: softmax over all 4 shown items
    ll <- ll + beta_full[best_item] - log(sum(exp(beta_full[shown])))

    # Worst pick: softmax over remaining 3 with negated utilities
    remaining <- shown[shown != best_item]
    ll <- ll - beta_full[worst_item] - log(sum(exp(-beta_full[remaining])))
  }

  return(ll)
}

# Maximize the log-likelihood with BFGS
set.seed(42)
mle_result <- optim(
  par     = rep(0, 9),
  fn      = log_likelihood,
  tasks   = tasks,
  method  = "BFGS",
  hessian = TRUE,
  control = list(fnscale = -1)   # fnscale = -1 tells optim to maximize
)

cat("Convergence (0 = success):", mle_result$convergence, "\n")
```

## MNL via Bayesian Estimation

We fit the same MNL using a **Metropolis-Hastings (MH)** MCMC sampler. Instead of a single point estimate, we get a full posterior distribution over each $\beta_j$.

**Prior:** $\boldsymbol\beta \sim \mathcal{N}(\mathbf{0},\ 10 \cdot I)$ — weakly informative (SD ≈ 3.2), letting the data dominate.

**Posterior:** $\pi(\boldsymbol\beta \mid \text{data}) \propto L(\boldsymbol\beta) \cdot \pi(\boldsymbol\beta)$

```{r}
# Log-posterior = log-likelihood + log-prior (N(0, 10) on each beta)
log_prior     <- function(beta) sum(dnorm(beta, 0, sqrt(10), log = TRUE))
log_posterior <- function(beta, tasks) log_likelihood(beta, tasks) + log_prior(beta)

# Metropolis-Hastings sampler
mh_sampler <- function(beta0, n_iter, step, tasks) {
  K      <- length(beta0)
  draws  <- matrix(NA, n_iter, K)
  beta   <- beta0
  lp     <- log_posterior(beta, tasks)
  accept <- 0

  for (t in 1:n_iter) {
    # Propose: random walk step
    beta_star <- beta + rnorm(K, 0, step)
    lp_star   <- log_posterior(beta_star, tasks)

    # Accept with MH probability
    if (log(runif(1)) < lp_star - lp) {
      beta   <- beta_star
      lp     <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  list(draws = draws, accept_rate = accept / n_iter)
}

# Run sampler — start from MLE estimate for faster convergence
set.seed(123)
n_iter      <- 20000
step        <- 0.08   # tuned for ~25-40% acceptance rate

cat("Running MCMC (20,000 iterations)...\n")
mcmc_result <- mh_sampler(mle_result$par, n_iter, step, tasks)
cat("Acceptance rate:", round(mcmc_result$accept_rate, 3), "\n")
```

## Discussion

**Substantive findings:** MSBA students most prefer Customer Analytics and Marketing Analytics — courses with direct career application. BI Systems and Capstone score lowest, possibly because students view them as requirements rather than elective interests, or because they are less directly associated with data science job skills.

**Methodological takeaways:**

| Method | Best for |
|---|---|
| **Counts** | Quick descriptive summary; executive dashboard; no modeling assumptions |
| **MLE MNL** | Rigorous point estimates with standard errors; single number to report |
| **Bayesian MNL** | Uncertainty on derived quantities (shares, simulations); hierarchical individual-level extensions |

**Caveats:** This survey was completed by a self-selected group of current MSBA students. Preferences may vary by prior work experience, course order, and academic background. Students who have already completed a class may rate it differently than those who have not yet taken it.

**Next steps:** With more time, I would extend the Bayesian model to a **hierarchical (mixed) MNL** — estimating individual-level $\beta$'s for each student — to reveal whether different subgroups have systematically different class preferences.
